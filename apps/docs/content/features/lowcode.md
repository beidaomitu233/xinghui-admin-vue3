# 低代码表单与记录

入口为 **通用能力 → 表单管理**（`/lowcode/forms`）。平台设计身份配合 `lowcode:form:list/query/add/edit/publish/remove`；填写/记录使用 `lowcode:record:list/query/add/edit/remove`。普通租户拥有记录权限可以使用已发布schema，不能修改平台设计。

## 设计、预览和发布

1. 点击“新增表单”，在“表单名称”填写“需求登记”，“表单标识”填写 `request_register`。标识是小写字母开头的稳定名称，创建后不能改。
2. 将左侧“单行文本”组件拖入画布，选中后在右侧设置标识`subject`、名称“需求主题”与必填；再拖入“多行文本”，设置`description`和“补充说明”。组件可重复拖入，画布使用手柄排序，也可点击添加、上移/下移。
3. 点击“预览填写”检查必填、默认值、选项与范围。预览只验证，不保存业务记录。
4. 保存草稿，刷新重新打开核对字段与顺序，再发布。草稿与发布版本分开，单独保存不影响正在填写的版本。

字段还可设置“字段帮助”、默认值、“列表显示”和“允许查询”；每项设置的技术字段及限制见下表和[Schema扩展](/development/lowcode-extension)。

| 类型 | 限制 |
| --- | --- |
| text / textarea | 默认200 / 5000字符，上限2000 / 5000 |
| number | 绝对值≤1e12、小数最多6位，可设min/max |
| date | 真实YYYY-MM-DD日期 |
| select / multiselect | 1–100选项，value支持0/1等非空ASCII字母数字下划线连字符；多选不支持查询条件 |
| switch | 真正boolean，false可以是有效必填值 |

最多100字段；fieldKey最长50，不能覆盖ID、tenant、creator、revision等系统字段。schema与data各最多256KiB UTF-8 JSON。当前没有字段联动、公式、附件或流程；分享设置支持登录填写和公开填写。

## 填写与管理

从表单列表打开 `/lowcode/runtime/{formId}` 填写、`/lowcode/records/{formId}` 管理。新提交带当前published schemaVersion；数据页按配置显示列和查询条件，详情/编辑使用记录原schemaVersion。停用阻止新增，历史记录仍可按权限编辑。

继续上例：点击该行“填写”，输入主题“改善列表筛选”和说明“增加状态过滤”，点击“提交记录”。页面显示“记录已保存”及编号；有列表权限时点击“数据列表”，应看到这条记录及填写版本1。点击“编辑”修改说明、保存，再刷新核对；点击“详情”只读查看，删除前确认具体记录。这个例子只在有权限且已授权的测试环境中操作，不要求创建新的业务模块。

普通租户可由管理员提供填写/数据深链，不需要表单设计列表权限。服务端runtime读取允许record五种权限任一种，填写页面仍要求add、数据列表要求list、详情要求query，编辑/删除各自授权。记录按tenant范围，不按creator限定为“仅本人”。

已有记录使用过的字段key/type不能删除或改变，包含软删除记录；允许兼容新增或修改标签/展示。发布失败时已保存草稿保留，先修复兼容性，不清空数据强行发布。record读写始终联合当前tenant、formId、recordId，不能仅凭recordId访问其他租户或表单。

## 分享给他人填写

1. 先发布，再打开“分享填写”。默认关闭，仅平台身份且有发布权限的管理员可配置。
2. 选择“登录后填写”或“公开填写”，启用并保存。公开填写需要确认；持链接的人无需后台账号即可提交，但不能查看已有答案。
3. 复制链接交给填写人，或在新窗口打开。填写页独立呈现，不显示管理菜单；登录模式引导登录并返回，同租户且账号正常才可继续。
4. 提交后显示回执。管理员在原表单数据页查看、筛选、编辑和删除记录，填写链接不授予管理权限。

撤销、重新生成、切换模式和停用都会使旧链接失效，重新启用不恢复旧链接。链接是访问凭据，勿放入公开日志。填写页不加载外部统计脚本，设置不发送来源地址。

失败保留输入，普通重试使用同一提交标识防重复。发布更新后旧版本提交被拒绝；用户确认重新加载且读取成功，才清空输入并开始新一次填写。不要把重新加载当作查询上次提交结果。

## 结果与恢复

保存后重新读取确认持久化；成功提交后再选择继续填写，避免重复数据。版本冲突先保留输入再重新读取；旧schemaVersion的新建请求拒绝。记录删除需要revision；存在历史记录的表单不能删除。没有读取权限不能直调API，隐藏按钮不替代后端检查。

## AI记录摘要

摘要复用现有表单记录及读取权限，配置见[提示词配置与业务摘要](/features/ai)。管理员在提示词配置中选择表单、允许字段和模型，合法保存后供新调用使用。本轮低代码数据来源支持实际schema中的全部可读业务字段，保留数字、布尔、数组和null，密码/密钥类字段排除；旧映射仍受原批准资源范围限制。管理配置权不代表记录读取或业务调用权。

本轮配置、数据预览、引用保存和对话阅读已原生验证，真实供应商限制及此前一期真实模型、SSE、日志与采纳保存刷新证据按[版本配对](../releases/versions.md)记录。本轮原生低代码摘要两次OpenRouter调用均上游超时，尚未完成本轮生成成功、采纳草稿到人工保存的正向实测；普通持久对话已验证两轮成功、四条消息保存，该结果不替代摘要场景验证。记录入口按当前有效场景和真实权限判断可用性，不要求填写应用ID或模板版本；静态演示不连接真实供应商。

用户填写摘要要求后生成，可取消、查询原请求或复制当前内容。服务端重新读取记录，保持原schemaVersion及类型/null，当前列表正文不是模型取数来源。受理、部分输出或连接断开不代表成功；新摘要进入持久化对话记录，刷新后可查看完整问答和继续追问，失败或部分输出准确标识。旧无正文请求明确提示未保留，不补造历史，也不因断线自动重发。

完整成功结果配合记录编辑权限，可选择长度合适的text/textarea字段“填入编辑草稿”。页面重新读取记录，用户检查后仍须点击原表单保存才入库。失败、超时或中断结果不能自动写入记录。Agent审批写与插件执行尚未交付。
