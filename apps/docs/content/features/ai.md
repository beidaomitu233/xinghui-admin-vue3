# AI对话、模型配置与数据库引用

AI管理包含三个独立页面：AI配置（`/ai/configurations`）管理渠道、Key与模型；提示词配置（`/ai/templates`）编辑场景与数据引用；调用监控（`/ai/requests`）查看完整对话和继续追问。场景合法保存后直接供新调用使用。

本页介绍完整对话、模型设置与实际数据库引用的使用流程。本轮配置、数据预览、引用保存和对话阅读已原生验证；真实供应商限制见[版本组合](../releases/versions.md)。公开演示使用虚构数据，不连接真实模型。

## 配置渠道、扫描模型与测试连接

### 模型中心

AI配置按业务模型组织，默认打开汇总；左侧切换“模型”和“供应商”，分别查看模型绑定和渠道接入。模型展示名称、稳定调用名称与上游服务商模型ID分开维护。汇总中的就绪和保障来自当前配置及已验证关联，不代表实时网络探测；多供应商按不同服务商计算，同服务商多个渠道不重复计数。

先添加渠道并配置Key、获取目录、选择上游模型及测试连接，再添加业务模型。业务模型可先保存为空绑定，之后添加供应商并选择其已配置的上游模型；可独立启停模型、绑定或渠道。上下调整调用顺序，选择优先级或轮询，并决定失败时是否自动切换。测试调用显示真实尝试过程，未知耗时保持未知，不模拟供应商成功。

提示词新场景可以选择业务模型。调整其供应商后，后续请求在受理时读取并固定当前模型与渠道版本，在途请求保持原快照。历史场景的Key限制与固定路线继续保留，不会自动放宽；改变绑定通过AI配置完成。已被场景引用的业务模型不能删除，调用名称创建后保持稳定。

模型能力与上下文窗口是配置说明，不扩大执行权限或令牌预算；当前文本调用不因此获得向量或视觉执行能力。目录与连接测试仍按以下流程分别操作。

1. 打开独立的 **AI配置** 页面，搜索已有渠道，或新增一个有可读名称的渠道，例如“日常问答主渠道”。选择OpenRouter或DeepSeek，系统使用所选服务商的官方地址。
2. 为该渠道添加命名Key，填写API Key并扫描模型。新Key可在保存前扫描，选择需要的模型后再保存，不需要先填写占位模型代码。已有Key可直接扫描；若正在替换Key，使用新输入的Key扫描。
3. 按模型名称或代码搜索目录，为每个Key勾选要使用的模型。一个Key可以对应多个模型，同一模型也可关联多个Key。扫描失败时保留已选模型，检查Key或稍后重试。
4. 保存渠道后，按需要确认连接测试会产生实际调用，再测试关联的Key与模型。具备启用权限时，可启用真实通过验证的项目。

扫描只读取模型目录，不发送生成问题，也不证明余额、额度或实际生成可用。OpenRouter带Key目录按账号偏好、隐私设置和防护规则筛选；DeepSeek目录采用其服务端实时模型信息。页面按名称和代码选择模型，连接测试单独显示真实结果；接口还提供扫描时间、上下文长度及已声明能力，未声明内容不猜测，见[模型扫描接口](../reference/api-catalog.md#模型目录与-key-扫描)。

每个渠道可保存1到16个命名Key、最多16个不同模型及64组Key与模型关联。编辑时，已有Key留空表示保留原值；删除Key或关联前核对仍有可用连接。保存后仅显示已配置和尾号标记，刷新后可确认状态。完整Key不回显，不进入浏览器持久化或对话消息；无需填写内部版本、配对ID或协议枚举。

已被场景使用的渠道不能直接换成另一服务商或地址；需要更换时新增渠道、验证连接，再在场景中调整候选。不要删除仍被使用模型的全部Key关联。

更换Key或模型后，新内容会显示待测试状态。原连接仍可继续运行；它此前的成功结果不代表新内容已经通过。可在设置中直接停用正在使用的配置。

保存不自动生成回答。连接测试按实际关联显示每个Key和模型的结果；同一模型只要有一个关联Key通过即可使用，其他Key的失败仍会显示。部分成功会同时说明已启用项目和未通过原因；没有项目通过、测试取消或配置已变化时保留原可用配置。测试与启用仍分别授权。

## 多渠道与掉线切换

多个渠道可以同时启用。在独立 **AI配置** 页维护场景调用顺序、候选模型及允许的Key；提示词页只显示模型概况并提供跳转入口。需要独立服务商备用时可分别配置OpenRouter和DeepSeek；同一服务商增加多个Key不能保证绕过该服务商整体故障。

执行时先尝试当前模型关联的合格Key，再按场景允许的备用顺序切换模型或渠道。网络故障、限流及部分供应商错误仅在尚未输出内容且仍有尝试、时间和令牌预算时切换；取消、权限/内容拒绝和已输出的回答不继续切换。Key鉴权失败会隔离该材料，修复后需重新测试。

如果已经输出部分回答后失败，保留部分内容并标明未完成，不接上另一模型的回答，也不将其当作成功轮次加入后续上下文。取消只停止后续执行，不能撤回已收到的内容。需要再次生成时由用户明确发起新请求。

## 查看和继续完整对话

从会话列表按可读标题、场景及最近时间找到对话，打开后按顺序查看用户消息、回答和真实状态。输入问题开始新会话，在同一会话中继续追问；后续模型上下文包含此前成功的问答轮次。

需要当前业务记录的场景，先按名称选择有权记录；不能从对话页选择的场景，应从对应业务记录入口开始。继续追问沿用同一记录，不能在会话中切换来源。

新对话正文保存在服务端，刷新或重新登录后可继续查看。失败、取消与部分输出如实保留，失败内容不会冒充完整回答参与后续上下文；同一会话有一轮正在执行时，等待或取消该轮后再提交新问题。请求受理不等于生成成功，断线应查询原请求，不自动重复生成。

历史上下文有轮数和容量上限，截断会说明从何处继续使用；展示历史不会因此删除。旧请求没有保存正文时显示“旧记录未保留对话”，系统不会补造回答。技术统计与请求详情可按需展开。

默认只能查看自己的对话。平台审计查看他人的记录需独立审计及查询权限；查看权限不允许冒充本人续聊。会话详情、续聊、正文、事件与取消都在服务端检查本人、租户、场景及实际数据权限。

## 编写提示词并引用真实数据

1. 在左侧选择或新增场景。记录摘要按名称绑定表单；新场景选择一个初始模型，后续Key与备用顺序到AI配置维护。
2. 在右侧编辑完整提示词。历史非空输出要求会合并进正文；用户要求与数据对象在引用列表中统一说明。
3. 点击添加引用，用一句话描述要取的数据。助手只接收当前账号有权看到的数据集结构，生成可编辑SQL；也可以直接填写SQL。
4. 核对查询范围，执行只读试查，确认字段、结果和条数后命名保存。引用表格说明数据对象、注入标识和查询来源，点击标识插入正文，例如 <code v-pre>{{order_summary:订单汇总}}</code>、<code v-pre>{{user_request:用户要求}}</code>。变量使用独立颜色，英文部分是稳定身份，中文部分帮助阅读。
5. 编辑停止后自动保存；只有服务端确认对应内容后才显示已保存。保存静态校验定义，不读取业务样本或调用模型；试运行才按当前真实身份取数并生成回答。

生成SQL、只读试查、保存引用与试运行是独立动作。模型生成失败不清空编辑内容，也不自动执行SQL；试查返回的有权数据不会因为生成SQL而自动发给供应商。需要当前业务记录的场景在试运行中提供记录上下文，正文区不堆放记录筛选和预览控件。

### SQL可以查询什么

查询助手展示当前账号获准的数据集、字段说明和范围。SQL使用这些数据集的名称，不直接开放整库。支持的语法由服务端返回，包括单条SELECT、明确字段、比较与AND/OR、受控INNER/LEFT JOIN、分组、排序和白名单聚合；UNION、子查询、CTE以及未支持的语法会明确拒绝。可以关联读取主子数据，但关联两侧均须授权。

SQL普通表来源当前不开放JSON、二进制及空间列；低代码多选字段按受控字符串数组读取。当前记录按真实可读单列主键定位，复合主键不伪装成单列。引用说明采用校验后的实际查询来源，选定的候选目录不会全部展示成已读取的数据。

当前租户、用户及业务记录参数由服务端绑定，不能通过填写SQL参数冒充他人。未知数据表、系统认证/配置/密钥等内部表、敏感字段不能查询；敏感字段也不能用于筛选、关联或表达式。模型隐藏系统提示词说明这些限制，实际权限由代码和数据库只读事务执行。

预览展示普通有权业务值，null、对象和数组保持结构。SQL查询结果通过HTTP返回时，数值使用精确字符串，并由列类型说明其含义，避免浏览器丢失长整数或小数精度；模型上下文仍使用原数值类型。SQL参数中的精确数值使用`{"$number":"9007199254740993123"}`，不能先转成JavaScript Number。值只替换一次，其中的花括号不会再次渲染；业务值不会成为SYSTEM指令、SQL或脚本。数据库密码、Key、令牌、认证配置等秘密不会进入上下文。

每个引用最多200行，新旧引用合计最多16项；独立试查结果最多256KiB，场景进入模型的总消息（提示词、数据和历史）最多64KiB，并受时限限制。超过范围需减少查询字段或条数。普通长文本可能截断并提示，无法安全解析或超限的结构化数据明确失败。

## 数据权限与恢复

每个数据集由服务端登记的业务政策授权。平台数据库来源仍需要明确的数据库读取权限及平台身份；租户端只能看到其业务政策允许的数据集。低代码读取沿用记录query/list与真实租户范围，不能因表有creator字段就猜测其他业务的个人权限。未明确的归属和权限政策会拒绝读取。

保存引用不会把创建者的权限授予其他调用者。运行时重新核对当前账号、租户、个人政策与软删除范围，关联和OR条件也不能取消这些限制。SQL必须通过完整语法检查并在专属强制只读事务执行；不允许写入、DDL、文件、锁、会话操作及危险函数。

新保存固定字段及取数定义；表后来新增列不会自动加入已保存的全字段引用。未知或删除的表/字段、无权记录或不兼容关联会明确失败。低代码按记录原schema读取，新字段尚未存在于旧记录时返回null并给出提示。

保存失败保留本地输入；无效输入不替换上次有效配置。409冲突时保留编辑并明确处理，不静默覆盖。模型暂不可用允许保存合法配置，但运行前仍需恢复可用模型。修改用于后续新调用，正在进行的回答保持本次内容不变。

## 记录摘要与旧配置

低代码记录摘要同样进入对话记录。具有业务调用和记录读取权限时生成，可继续追问、取消或复制。完整成功结果需用户显式填入长度合适的文字字段草稿，再检查并点击原表单保存；不会自动写入业务记录。

已有场景及原数据授权继续保留。支持转换的旧配置会先展示差异并要求确认，不能自动转换时保持只读并保留原内容。若需使用新的数据库来源，可新增场景并选择有权数据；新增引用不能绕过原授权限制。

旧字段、整条记录、整表与关联子表引用继续按固定定义运行，原 <code v-pre>{{客户.名称}}</code>、<code v-pre>{{user_request}}</code> 等标记继续可读。编辑正文不会自动改写Key策略，也不会因表新增列扩大旧引用范围。

旧AI02读取链路与历史请求保留。Agent、插件、工具执行和审批写入仍未交付。技术合同见[场景与数据扩展](../development/ai-extension.md)及[查询助手API](../reference/api-catalog.md#提示词查询助手与独立路由)。
