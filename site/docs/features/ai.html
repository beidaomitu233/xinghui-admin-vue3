AI模型、模板与业务摘要 ​

旧入口为 通用能力 → AI模型、提示词场景，继续使用 ai:model:* / ai:prompt:* 权限。v0.4 新增 AI管理下的模板、受控数据引用及应用运行接缝；配置管理权限与业务读取权限分别检查。

当前交付边界 ​

范围当前状态
旧模型、appKey/sceneKey场景与受控渲染保留原读取链路和已有数据
独立配置、模板、批准资源版本、预览及模板选项当前源码一期已通过正式CI及真实认证、HTTP和页面组合验收，预览保持精确发布版本并脱敏
低代码记录摘要、应用发布、SSE及请求日志已验证真实模型生成、采纳编辑草稿、人工保存、刷新和数据库revision；不代表静态演示或任意部署已启用
Agent、插件执行、任意SQL/脚本取数尚未交付

以下 v0.4 操作对应当前源码版本配对，需部署真实后端、完成迁移和权限/模型配置。v1.2.0是已发布静态旧快照，当前源码一期新增AI尚无独立发行Tag。2026-10-17 Pages 更新仅提供一期 AI 页面与虚构只读数据，不能进行真实生成、测试或审批。模板预览成功只证明授权取数与渲染，仍不能单独替代模型测试或应用发布证据。

旧模型操作 ​

在模型页点击“新增模型”，填写“供应方标识”“模型代号”“HTTPS 服务端点”“凭据环境变量名”“超时（秒）”，并选择启停状态。仅使用已获授权的模型信息。技术请求字段分别为providerCode、modelCode、endpointUrl、credentialEnvName、timeoutSeconds、enabled。凭据来源为ENV或加密DB，GET仅返回配置标记；数据库模式要求稳定CONFIG_MASTER_KEY。更新、启停、删除及凭据保存携带revision，冲突后重新读取，不覆盖他人的最新修改。

模型测试当前仅支持官方OpenRouter端点。点击模型行“测试模型”后，必须看结果内容，不能只看API返回200。当前Controller将测试Outcome放入Result.ok：例如外层HTTP200/code200，内层 data.outcome="RATE_LIMITED"、data.httpStatus=429，代表供应方调用失败于限流。只有SUCCESS才是模型测试成功；AUTH_FAILED、MODEL_MISMATCH、TIMEOUT等各有不同恢复方式。测试可能调用外部供应商并产生计费，须在部署与授权明确后使用，不因教程示例自动发请求。

旧场景流程 ​

  1. 打开新增场景草稿，在“应用标识”填写 example_app、“场景标识”填写 summary，选择一个已有“启用模型”。这里的example_app只是中性设计示例，未注册业务resolver时不能运行读取。
  2. 在“提示词草稿”填写 概述：{{subject}}，点击“添加变量声明”，填写变量名subject，类型选择“文本”，用途说明填写“中性主题”，示例值填写“界面调整”。
  3. 点击“保存草稿”，从列表“预览”进入“场景中性预览”，点击“生成中性预览”；应得到“概述：界面调整”。预览是文本渲染，不是模型调用，敏感变量会掩码。
  4. 点击列表“发布”并确认，详情中的“已发布快照”应出现版本。业务使用published版本；再次编辑“提示词草稿”不改变已发布内容。发布与启停使用revision。

占位符使用 {{name}}；类型“文本/数字/布尔值”分别对应STRING/NUMBER/BOOLEAN，变量声明含description、sensitive、exampleValue。变量未声明、缺值或类型不符时先修正声明和输入，不把预览错误当成供应商连接错误。

正文最长12000字符、最多64变量；单个预览/运行变量最长2048字符，exampleValue最长512。appKey/sceneKey创建后稳定，不能靠改名复用其他应用资源。

旧场景业务读取与恢复 ​

POST /ai/scenes/{appKey}/{sceneKey}/render只渲染已注册应用、已发布启用场景。接缝验证认证、业务动作、资源归属与租户，然后解析变量；不会直接发送模型请求或保存业务正文。未注册应用、缺变量、越权、停用场景与输出超长有明确拒绝结果。

没有证明两个独立业务系统已实际采用，也没有通用聊天、自动Agent或任意SQL/脚本变量能力。新业务注册方式见AI扩展。

v0.4 独立模板与数据引用 ​

新入口为 AI管理 → 提示词模板（/ai/templates）。页面内有“模板”“数据引用”两个 Tab，分别需要 ai:template:*、ai:data:* 动作权限。“旧场景兼容映射”只读展示原场景标识、关联模型和当前修订；旧场景页面与 /ai/scenes/.../render 保留。旧表只有当前发布快照，不能把它当成完整历史，也不会自动转成新应用绑定。

配置与发布顺序 ​

先准备真实表单、记录、目标应用的稳定ID和负责测试的业务身份。当前源码已验证配置、资源、模板与应用发布组合；下面从已有应用草稿开始，不应为了通过测试编造应用ID或生产业务数据。首次安装与升级按部署教程及版本配对确认迁移与服务配置。

  1. 在数据引用 Tab 新增资源。来源固定为代码注册的“低代码表单记录（只读）”；填写真实表单ID、允许返回的字段标识、负责人、业务域、允许用户ID及应用ID。ID按字符串处理，不要在 JavaScript 中转换为数字。
  2. 用当前登录身份填写应用ID和 formId:recordId，执行测试。测试只报告授权字段、记录原始结构版本及结果分类，不显示业务原值。管理权限不会赋予 lowcode:record:query 业务权限，也不能切换成任意测试用户。
  3. 成功测试当前配置后提交审批。具有审批动作权限的人员核对配置和测试证据，批准时生成不可变资源版本并启用；拒绝不会生成版本。修改字段、表单、允许主体/应用或其他参数后，当前草稿必须重新测试、审批。
  4. 在模板 Tab 填写名称、用途、负责人。系统指令写固定文字；用户输入与业务数据分别写消息，通过 {{变量名}} 引用各自变量。变量支持文本、数字、布尔、对象、数组，以及必填、显式默认值、敏感与长度策略。
  5. 添加数据引用，填写资源ID和批准版本ID，每行配置 批准字段=变量名。低代码参数固定来自本次业务引用。必需资源失败会阻止后续模型调用；可选资源只有显式允许时才省略缺记录或合法空数据，权限拒绝与超时仍然失败。
  6. 保存模板，用当前身份预览、测试，通过后发布。发布生成独立模板版本。应用固定绑定精确模板/资源版本；新模板发布不会自动升级应用，应用须重新测试并显式升级。应用发布、实际业务调用与请求日志见对应应用页面，模板预览本身不会调用模型。

例如，复用低代码表单示例中的 subject 字段时，可批准资源只返回 subject，映射 subject=record_subject。模板声明 user_request 为必填文本输入，record_subject 为资源文本变量；用户输入消息写 {{user_request}}，业务数据消息写 主题：{{record_subject}}。记录摘要入口会把用户填写的摘要要求传为 user_request，记录正文由服务端重新读取。示例中的字段名须与真实记录原结构一致，不能照抄成任意表单的字段。

模板行的预览读取当前草稿，按需展开“模板原文”“输入（脱敏）”“引用字段（脱敏）”“最终消息（脱敏）”及缺省/截断元数据。输入/引用摘要统一脱敏，最终消息按敏感变量和资源变量脱敏；查看成功不能作为拥有其他记录读取权限的证明。

应用选择精确模板版本 ​

应用使用已发布模板选项，展示每个历史版本的名称、精确版本ID、输入变量和资源版本。未发布草稿不会进入候选项；应用选择后保留原绑定，后续发布不会自动改成最新版本。

不可用候选项会给出固定原因：模板停用、资源停用/缺失、资源批准证据失效、字段不在批准范围、应用不在资源允许范围，或配置无效。修复后须重新执行应用测试与发布检查；下拉显示“可用”并不能替代运行授权。应用负责人可凭应用查询/新增/编辑/测试权限读取这些安全选项，无需获得模板编辑权限，也不会因此看到消息或默认值。

应用绑定版本的管理预览与模板草稿预览分开。精确版本预览按应用已绑定的发布版本取原文并授权取数；例如应用绑定v1、模板草稿已改v2，预览仍使用v1。解析后的输入、默认值和业务变量全部掩码，摘要仅给安全分类。该HTTP/UI组合已验收；预览不调用模型、不生成模型请求，也不能作为应用发布所需的成功模型测试证明。

版本与恢复 ​

列表中的“版本与引用”可读取历史、并排比较两个版本，并查询某一版本的应用引用。资源测试和审批证据只保存结果分类、配置哈希、操作者和时间，不保存业务样本。停用模板或资源会阻止后续请求，历史仍保留。重新启用资源要求当前配置已批准。

输入只能做单次占位符替换，值中的 {{...}} 不会再次渲染。超长文本仅在变量明确允许时截断，并返回截断元数据；对象/数组不截断，渲染后消息仍受总长度限制。敏感输入及所有资源值在预览中脱敏，响应禁止缓存。

首个实际来源复用现有低代码服务，按真实身份、租户、表单和记录读取，使用记录的原始 schemaVersion，仅提取批准字段。现有低代码服务没有额外的逐字段角色授权；本期字段范围由获批资源配置进一步收窄。未开放任意URL、SQL、脚本、Bean名称或动态Java类型。Agent与插件运行属于后续阶段，尚未交付。

真实表单记录摘要入口（当前源码一期已验收） ​

此入口复用现有表单记录，不要求新建订单或其他业务模块。部署完成后，具有记录列表/查询权限、且服务端能为该表单找到已启用发布应用时，记录行才显示“AI摘要”。应用和记录授权仍在服务端执行；页面不接收用户手填应用ID或把当前列表正文当作模型数据。静态演示环境不启用真实摘要入口。

  1. 打开一条有权读取的记录，点击“AI摘要”，填写“摘要要求”，再点击“生成摘要”。
  2. 查看请求ID、应用版本及明确状态。连接关闭、收到部分文字或仅有受理成功，都不代表生成成功。取消只请求停止后续处理，不能撤销上游已经执行的动作。
  3. 断线后选择“查询原请求”；受理结果不明确时确认原受理结果，避免创建重复请求。刷新后可查询原状态，历史正文未保存则无法恢复，不会自动重新生成。
  4. 可复制当前内容。只有收到完整成功结果且具有记录编辑权限时，才可选择长度容得下的文字字段，点击“填入编辑草稿”。页面会重新读取记录再填入草稿，仍须检查内容并显式保存，生成结果不会自动写记录。

真实供应商失败、限流、超时或输出中断须如实展示，不能以模拟输出补成成功。完整表单→授权取数→模板→真实模型→SSE→日志及采纳保存刷新链路已在当前配对源码验收；供应商可用性仍随模型、账户和时间变化。专用MySQL验证资源读取等待可取消、阻塞语句在语句时限内终止；本次驱动没有因线程中断立即终止语句，不能把它称为即时数据库取消。Agent审批写、工具执行和持久会话尚未交付。
